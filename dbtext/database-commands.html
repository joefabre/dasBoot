CREATE TABLE

Creates a new table in the database with specified columns and constraints.

How CREATE TABLE Works

Purpose: Defines the structure of a new table by specifying column names, data types, and constraints.

Function: The database engine creates a new empty table with the defined schema. Each column must have a data type (INT, VARCHAR, DATE, etc.) and can include constraints like NOT NULL, UNIQUE, or PRIMARY KEY.

Impact: Once created, the table becomes available for data insertion, querying, and modification operations.

Common Use Cases

  • Setting up initial database schema for new applications
  • Creating lookup tables for reference data
  • Establishing relationships between entities with foreign keys
  • Creating temporary tables for data processing
Basic Table Creation
CREATE TABLE employees ( id INT PRIMARY KEY, first_name VARCHAR(50) NOT NULL, last_name VARCHAR(50) NOT NULL, email VARCHAR(100) UNIQUE, hire_date DATE, salary DECIMAL(10,2) );
Table with Auto-Increment and Foreign Key
CREATE TABLE orders ( order_id INT AUTO_INCREMENT PRIMARY KEY, customer_id INT, order_date DATETIME DEFAULT CURRENT_TIMESTAMP, total_amount DECIMAL(10,2), FOREIGN KEY (customer_id) REFERENCES customers(id) );

SELECT

Retrieves data from one or more tables based on specified criteria.

How SELECT Works

Purpose: Queries the database to extract specific data from tables based on conditions you specify.

Function: The database engine scans through table rows, applies WHERE conditions to filter data, sorts results if ORDER BY is specified, and returns only the columns you've selected. It's the most fundamental operation for data retrieval.

Performance: Can use indexes to speed up searches. Without proper indexing on WHERE clause columns, it may scan entire tables.

Impact: Read-only operation that doesn't modify data, but can consume significant resources on large datasets.

Common Use Cases

  • Generating reports and analytics from business data
  • Populating user interfaces with dynamic content
  • Data validation and quality checks
  • Exporting data for external systems
  • Building dashboards and monitoring systems
Basic SELECT
SELECT first_name, last_name, email FROM employees WHERE salary > 50000;
SELECT with ORDER BY and LIMIT
SELECT * FROM employees WHERE department = 'Sales' ORDER BY hire_date DESC LIMIT 10;

INNER JOIN

Returns records that have matching values in both tables.

How INNER JOIN Works

Purpose: Combines rows from two or more tables based on a related column between them.

Function: The database engine compares each row in the first table with every row in the second table. When the join condition is met (usually equality between foreign key and primary key), it creates a new row containing columns from both tables.

Result: Only returns rows where there's a match in both tables. Rows without matches are excluded from the result set.

Performance: Benefits greatly from indexes on the join columns. Large table joins can be resource-intensive.

Common Use Cases

  • Retrieving customer information with their orders
  • Combining employee data with department details
  • Joining product information with category data
  • Merging user profiles with their activity logs
  • Creating comprehensive reports from normalized tables
Basic INNER JOIN
SELECT e.first_name, e.last_name, d.department_name FROM employees e INNER JOIN departments d ON e.department_id = d.id WHERE e.status = 'active';

MongoDB Find

Retrieves documents from a MongoDB collection based on query criteria.

How MongoDB Find Works

Purpose: Queries a MongoDB collection to retrieve documents that match specified criteria using MongoDB's flexible document-based query language.

Function: MongoDB scans the collection and evaluates each document against the query filter. It supports complex queries using operators like $gt, $lt, $in, $and, $or, and many others. Unlike SQL, it works with nested objects and arrays naturally.

Flexibility: Can query nested fields, array elements, and use powerful aggregation operators. Supports projection to return only specific fields.

Performance: Benefits from indexes on frequently queried fields. Can use compound indexes for multi-field queries.

Common Use Cases

  • Retrieving user profiles and preferences
  • Searching products by multiple criteria (price, category, ratings)
  • Finding documents with nested data structures
  • Querying arrays and embedded documents
  • Building flexible search and filter functionality
  • Real-time data retrieval for web applications
Basic Find Query
// Find all users with age greater than 25 db.users.find({ age: { $gt: 25 } }); // Find with specific fields db.users.find( { status: "active" }, { name: 1, email: 1, _id: 0 } );
Advanced Find with Sorting and Limiting
// Find with complex query, sort and limit db.products.find({ $and: [ { price: { $gte: 100 } }, { category: "electronics" } ] }) .sort({ price: -1 }) .limit(10);
